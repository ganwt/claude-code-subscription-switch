## 本机实验（决定架构的两个假设）

### 实验 1：apiKeyHelper 热重载能否切换运行中的会话 —— 成立

方法：在 `/tmp` 临时项目的 `.claude/settings.json` 里用 statusLine 记录每次响应，运行一个 haiku 会话；中途写入指向"输出无效 key 的脚本"的 `apiKeyHelper`，再删除。

结果（时间线）：
- 17:56:10 发第 1 条 → 订阅成功，statusLine 有 `rate_limits`。
- 17:56:40 写入 apiKeyHelper → 17:56:48 发第 2 条 → 17:56:49 helper 被调用，请求以 `401 invalid x-api-key` 失败并开始重试；界面标题从 "Claude Team" 变为 "API Usage Billing"。
- 17:57:19 删除 apiKeyHelper → 仍在重试的那条请求于 17:57:28 用订阅成功，`rate_limits` 重新出现。
- 第 3 条正常。

结论：settings.json 的 apiKeyHelper 增删会在**同一会话的下一次请求**生效，双向都成立，无需重启。项目级 settings 也有效。

### 实验 2：扩展是否执行 statusLine / 触发 hooks —— hooks 触发，statusLine 不执行

真实使用两天后的证据（2026-10-27 检查）：
- 2026-10-25 安装后到 10-27 之间 Remote-WSL 扩展产生了多个会话（`~/.claude/projects/` 下有新的会话文件），但 `state.json` 的 `sessions` 只有安装当天 CLI 测试的两条——扩展**不执行 statusLine 命令**。
- `switch.log` 里有 2026-10-26 01:47 `STOPFAILURE error=rate_limit`（来自扩展会话）和 08:22 `SWITCH api -> max ... [check]`（Stop hook 触发）——扩展**会触发 hooks**。

结论：扩展环境只能走 hook 路径。耗尽检测靠 `StopFailure rate_limit` + 错误文本，恢复靠 `Stop` hook 的定时检查，不计费。

### 真实限额命中记录（2026-10-26）

```text
01:47:05 STOPFAILURE error=rate_limit effective=max detail="You've hit your session limit · resets 3:30am (Asia/Tokyo)"
01:47:05 SWITCH max -> api (subscription exhausted: five_hour=100%, recover at 06:47 [stop-failure rate_limit (usage data stale)])
01:47:05 VERIFY auth status = api_key_helper OK
08:22:17 SWITCH api -> max (subscription window reset [check])
08:22:17 VERIFY auth status = claude.ai OK
```

- 验证了此前的假设：订阅限额命中时 `StopFailure.error == rate_limit`，`last_assistant_message` 带有重置时间。
- 暴露的问题：当时没有 statusLine 数据，恢复时间按"现在 + 5 小时"估算成 06:47，实际 03:30 就已重置。已改进：从错误文本解析 `resets 3:30am (Asia/Tokyo)` / `resets Mon 12:00am`，解析不到才用 `unknown_reset_fallback_sec`。
- 同时收紧了判定：`rate_limit` 只有在错误文本是 "hit/reached your … limit"、或最近用量 ≥ guard 时才算耗尽；普通 429 不再因为"数据过期"触发切换。

### 模型专属限额（Fable / Opus / Sonnet limit）

- 2.1.299 的 statusLine schema 里除 `five_hour`、`seven_day` 外还有 `seven_day_opus`、`seven_day_sonnet`、`model_scoped[]`（`display_name`、`utilization`、`resets_at`），但注释说明 `model_scoped` 按"额外用量包含的模型"过滤；本账户额外用量被禁用，实测只返回 `five_hour`。
- 程序已支持这些字段，并只把属于当前模型的窗口计入（Sonnet 窗口不会把 Fable 会话推到 API）。
- 错误文本 "You've reached your Fable limit" 同样是 `rate_limit`，现在会记为 `model:Fable` 窗口并切换；该文本不含重置时间，恢复用 fallback（默认 5 小时），到期切回后若仍受限会再次触发（每 5 小时一次失败请求）。

## 端到端测试（真实 settings.json，无效 key，不产生费用）

步骤：`install.sh` → `set-key` 存入 `sk-ant-api03-INVALID-...` → `set-mode api` → 在临时目录运行 haiku 会话发一条消息 → 等待 → `/exit`。

结果：
- 安装后 settings.json 只新增 `statusLine`、`hooks.StopFailure`、`hooks.Stop`，原有键保留；备份写入 `~/.claude/backups/claude-switch/`。
- `set-mode api` 后 `claude auth status`（新进程）= `api_key_helper`，日志 `VERIFY ... OK`；会话标题 "API Usage Billing"，状态栏显示 `API (forced) · today $0.00/5`。
- 请求 401，Claude Code 自己重试 10 次（约 4 分 12 秒）后放弃；**`StopFailure` 触发，`error=authentication_failed`**，`last_assistant_message` = "Invalid API key · Fix external API key"。
- hook 记录 `API BLOCKED`。第一轮测试里因为处于强制 api 模式没有切回，已修正：API 被锁定时无论何种模式都切回订阅（场景 9c 覆盖）。
- 测试后删除了无效 key 文件；当前状态 `mode=auto effective=max`，apiKeyHelper 不存在。
